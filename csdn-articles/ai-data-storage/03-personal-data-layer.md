# 每个开发者都需要一个「个人数据层」——不是数据库，是你的第二大脑

我现在在三个 AI 工具之间来回切换：Claude Code 写代码，Codex 做快速原型，OpenClaw 跑后台任务。

但有一个问题越来越烦：它们互相不认识。

Claude Code 不知道我在 Codex 里做过什么。Codex 不知道我在 OpenClaw 里配置了什么。每次换工具都像搬家——要把项目背景、技术偏好、常用命令重新说一遍。

我开始想：能不能有一个东西，独立于所有 AI 工具之外，专门存「我自己」的数据？

---

## 你的数据散落在哪

打开你的电脑，属于「你这个人」的数据大概在：

```
~/projects/           → 项目代码
~/.claude/            → Claude Code 的配置和 Skill
~/.codex/             → Codex 的 Thread 历史
~/notes/              → 零散的 Markdown 笔记
~/csdn-drafts/        → 写了一半的文章
浏览器书签             → 各种技术文档链接
GitHub Stars           → 收藏的开源项目
```

这些东西合在一起，其实构成了你作为一个开发者的「知识画像」——你用什么技术栈、你最近在学什么、你做过哪些项目、你做技术决策时倾向什么方案。

但问题是：**它们散落在七个不同的地方，彼此之间没有任何连接。** 你手动检索的效率很低，AI 工具也访问不到——Codex 读不到你的 Markdown 笔记，Claude Code 不知道你 GitHub Stars 里收藏了什么。

---

## 个人数据层长什么样

不是让你再搭一个数据库。它的核心能力就三样：

**存**：自动从你日常使用的工具中收集关键信息——不是所有信息，是「以后可能会用到」的部分。

**查**：不光你自己能查，你的 AI 工具也能查。语义检索——不用想「那个文件叫啥名字」，直接想「那个关于连接池的内容」。

**推**：在你需要的时候主动推送相关上下文。比如你在写一篇关于 Agent 调试的文章，它自动找到你三个月前记的一篇调试笔记。

具体到实现上，它大概是这样：

```
个人数据层
├── 项目知识（每个项目的技术栈、架构决策、关键配置）
├── 技术笔记（你写的、AI 帮你总结的、从文档中提取的）
├── 决策记录（为什么选 A 不选 B、当时的上下文是什么）
├── 偏好设置（你习惯的代码风格、常用的解决方案）
└── 搜索索引（以上所有内容的语义索引）
```

它不需要你手动维护。你在 Claude Code 里做了一次架构决策，它自动提取关键信息存进去。你在 Codex 里解决了一个奇怪的 Bug，它把根因和解决方案记下来。你在 OpenClaw 里跑完了一个长期任务，它把结果摘要存起来。

这就是「被动收集，主动推送」——跟传统的文件系统正好相反。

## 我现在的做法

目前我用的是一个很简单的方案：一个本地目录 + 一个定期扫描脚本。

```bash
# 目录结构
~/.personal-layer/
├── projects/          # 每个项目的知识卡片
│   ├── harmonyos.json
│   └── agent-project.json
├── notes/             # 笔记（.md）
├── decisions/         # 决策记录
└── index/             # Chroma 向量索引
```

`projects/harmonyos.json` 大概长这样：

```json
{
  "name": "HarmonyOS 开发助手",
  "tech_stack": ["Python", "FastAPI", "Milvus", "Next.js"],
  "key_decisions": [
    "选择 Milvus 而不是 Pinecone，因为数据合规要求",
    "放弃自研 Embedding，改用 BGE-Large-ZH"
  ],
  "gotchas": [
    "Milvus 的 get_or_create_collection 不会检查集合是否已存在",
    "relationalStore 的 ResultSet 必须手动 close"
  ],
  "last_updated": "2026-05-15"
}
```

每次启动 Claude Code 时，一个脚本会自动把这个 JSON 注入到 CLAUDE.md 里。不是全文，是只取跟当前任务最相关的前 5 条。

效果很直接：AI 不需要我再解释项目背景了。它上来就知道这个项目用什么技术栈、之前踩过什么坑。

我知道这个方案很原始。但它验证了一个想法：**你不需要一个复杂系统，只需要一个独立于 AI 工具的数据层。** 即使只有几 KB 的结构化数据，也能让 AI 的表现完全不同。

---

## 为什么 AI 公司不会帮你做这个

Claude Code 有 CLAUDE.md，Codex 有 Thread 历史，OpenClaw 有 Skill 系统。

但 CLAUDE.md 只有 Claude Code 能读。Codex 的 Thread 只有 Codex 能访问。每个工具都在自己的沙盒里存用户数据。

这不是它们做不到，是它们没有动力做。让你的数据可以跨工具流动，等于降低了切换成本——这不符合任何一家 AI 公司的商业利益。

所以这个「个人数据层」只能你自己搭。不需要很复杂。几百行 Python，一个 Chroma 数据库，几个自动扫描脚本。关键是意识到**你需要它**——不是以后需要，是现在就需要。

## 一年后回头看

我预测一个趋势：一年之内会有人把「个人数据层」做成开源项目。不是 memo.ai 那种全自动记录一切的工具——那种太耗资源而且数据噪音太大。而是轻量的、聚焦的、只为 AI 编程助手服务的上下文管理工具。

因为在 2026 年，一个开发者的知识增长速度是被 AI 加速过的。你每天产出的技术决策、调试经验、架构思考，比三年前多了好几倍。如果存储方式不跟上，你会越来越频繁地遇到「我记得我做过这件事，但我找不到记录」。

而当你需要把这个数据层接入 AI 工具时，MCP 协议刚好就是标准化的接口。你写一个 MCP Server，暴露三个能力：存知识、查知识、推送相关上下文。然后所有支持 MCP 的 AI 工具——Claude Code、Codex、Cursor——全部能用。

这可能是 2026 年下半年最值得做的开源项目之一。
