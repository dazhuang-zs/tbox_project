## 开篇：那次凌晨三点的复盘，让我再也不敢忽略复杂度

2019年我负责一个用户标签系统的开发。功能很简单：给100万用户打标签，每个用户根据消费记录匹配对应的标签。

我写的代码逻辑大概是：遍历100万用户 → 每个用户去100万条消费记录里找匹配 → 打标签。

上线后，这个任务跑了3小时还没结束。

凌晨三点被运维电话叫醒，一查：**O(n²) = 100万 × 100万 = 1万亿次操作**。不是程序挂了，是它还在跑——只是这辈子可能跑不完。

后来改成：先把消费记录按用户ID建一个HashMap → 遍历用户时直接O(1)取——跑完只用了8分钟。

**O(n²)到O(n)，从"跑不完"到8分钟。这就是算法复杂度的全部意义。**

当时我就明白了一件事：复杂度不是面试题。是你写的代码在数据量变大之后，会不会把你从床上拉起来的依据。

## 一、时间复杂度到底是什么——用你每天写代码的语言讲

### 教科书定义（30秒版）

时间复杂度描述的是：**当输入数据量n变大时，算法执行时间的增长趋势。**

不是精确时间（秒），是增长曲线。

### 人话版（你真正需要懂的）

你有没有注意到一个现象：同样的代码，100条数据时秒出结果，1万条时要等几秒，10万条时直接卡死？

这不是bug，是**你的代码对N的敏感度**不同。

```python
# 这段代码：N=100只要0.001秒，N=10万要10秒
for user in users:          # N次
    for product in products:  # N次
        if user.id == product.user_id:  # 1次
            tag(user, product)
# 总操作次数 ≈ N × N = N²
# N=100 → 1万次，瞬间完成
# N=10万 → 100亿次，要十几秒
# N=100万 → 1万亿次，这辈子跑不完
```

时间复杂度的核心问题只有一个：**你的代码里，N出现了几次方？**

## 二、7个最常见的时间复杂度——从快到慢一目了然

用同一个场景来对比：**在100万条数据中查找一个值。**

| 复杂度 | 100万数据要多少次操作 | 类比 | 代码特征 |
|--------|---------------------|------|---------|
| **O(1)** | 1次 | 打开一本书的指定页码 | 数组下标访问、HashMap.get() |
| **O(log n)** | ~20次 | 翻字典找"复杂度"这个词 | 二分查找、平衡树 |
| **O(n)** | 100万次 | 从第一页翻到最后一页 | 一次循环、遍历数组 |
| **O(n log n)** | ~2000万次 | 整理乱序的书架 | 快速排序、归并排序 |
| **O(n²)** | 1万亿次 | 每个人和每个人握一次手 | 嵌套循环、冒泡排序 |
| **O(2^n)** | 2^100万（宇宙年龄都不够） | 枚举所有子集 | 递归求斐波那契（无记忆化） |
| **O(n!)** | 100万!（别想了） | 枚举所有排列 | 旅行商问题的暴力解法 |

### 每个复杂度写一段代码，让你彻底记住

**O(1)——常数时间：不管N多大，操作次数不变**

```python
def get_first(arr):
    return arr[0]  # N=100还是N=1亿，都是1次操作

def lookup_user(user_id):
    return user_map[user_id]  # HashMap.get() → O(1)
```
> 现实意义：你的代码里如果有一个O(1)的操作替代了O(n)的操作，数据量大时差距是天壤之别。

**O(log n)——对数时间：N翻倍，操作次数只+1**

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
# N=100万 → 最多比较20次
# 为什么是log₂(1000000) ≈ 20？
# 因为每次比较排除一半：100万→50万→25万→...→1（20步）
```
> 关键认知：O(log n)的算法几乎和O(1)一样好。N从100万涨到10亿，O(1)操作次数不变，O(log n)只从20次涨到30次。

**O(n)——线性时间：N翻倍，操作次数翻倍**

```python
def find_max(arr):
    max_val = arr[0]
    for num in arr:       # 循环N次
        if num > max_val:
            max_val = num
    return max_val

def count_words(text):
    word_count = {}
    for word in text.split():  # 每个单词一次
        word_count[word] = word_count.get(word, 0) + 1
    return word_count
```
> 现实意义：O(n)通常是最优解——你必须处理每一个输入。如果算法能做到O(n)以下，说明你有办法"不看"某些数据（如二分查找）。

**O(n log n)——线性对数：比O(n)多一个"排序"的代价**

```python
# 快速排序：每次找一个基准值，大的放右边小的放左边
def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quicksort(left) + middle + quicksort(right)
```
> 核心理解：O(n log n) = n × log n。n是因为"每一层都要遍历所有元素"，log n是因为"每次把问题拆成两半"。这就是所有比较排序（快排、归并、堆排）的下限——不可能比O(n log n)更快了，因为n个元素的排列有n!种可能，你需要log₂(n!) ≈ n log n次比较才能确定顺序。

**O(n²)——平方时间：循环套循环，代码里的头号杀手**

```python
# 检查数组里有没有重复元素——暴力法
def has_duplicate(arr):
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False
# N=1000 → 约50万次比较（还行）
# N=10万 → 约50亿次比较（十几秒）
# N=100万 → 约5000亿次比较（别等了）

# 优化：用HashSet → O(n)
def has_duplicate_fast(arr):
    seen = set()
    for x in arr:
        if x in seen:  # set的in操作 → O(1)
            return True
        seen.add(x)
    return False
```
> 我凌晨三点爬起来修的bug就是这种。**每当你写了一个嵌套循环，停下来问自己：能不能用HashMap/Set把内层循环干掉？**

**O(2^n)——指数时间：每多一个元素，时间翻倍**

```python
# 计算斐波那契数列第n项——最蠢的递归
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)
# fib(5) → 调15次
# fib(10) → 调177次
# fib(40) → 调3亿多次，跑几十秒
# fib(50) → 算了别跑了

# 优化：加个记忆 → O(n)
memo = {}
def fib_memo(n):
    if n <= 1: return n
    if n not in memo:
        memo[n] = fib_memo(n-1) + fib_memo(n-2)
    return memo[n]
```

## 三、怎么写一眼看出时间复杂度——3步速判法

### 第1步：找到N是什么

N = 输入数据的规模。通常就是数组长度、字符串长度、二叉树节点数。

```python
def process(users):       # N = len(users)
    for u in users:       # 循环N次
        pass
```

### 第2步：数循环层数，但注意"隐藏的循环"

```python
# 明确的一层循环 → O(n)
for x in arr:
    print(x)

# 明确的两层嵌套 → O(n²)
for i in range(n):
    for j in range(n):
        print(i, j)

# 隐藏的循环！→ 也是O(n²)
for x in arr:           # O(n)
    if x in another_arr:  # Python的list的in操作 → O(n)!
        print(x)
# 总复杂度 O(n²)，因为内层的in也需要遍历
```

**常见隐藏循环**：
- Python: `x in list` → O(n)，但 `x in set` → O(1)
- Java: `ArrayList.contains()` → O(n)，`HashSet.contains()` → O(1)
- `min(arr)`, `max(arr)`, `sum(arr)` → 都是O(n)，因为要遍历全部

### 第3步：取增长最快的项

```python
# 这段代码的复杂度：
for x in arr:             # O(n)
    print(x)

for i in range(n):        # O(n²)
    for j in range(n):
        print(i * j)

# 总复杂度 = O(n + n²) = O(n²)
# 保留增长最快的项，系数不要
```

**速算口诀**：
- 一个循环 → O(n)
- 两个独立循环 → O(n)，不是O(2n)
- 循环套循环 → O(n²)
- 循环每次减半 → O(log n)
- 循环里套减半 → O(n log n)

## 四、递归的复杂度怎么算——主定理速算表

递归的复杂度不能光看层数，得用**主定理**。但不用背公式，记住这张速查表就行：

| 递归公式 | 对应算法 | 复杂度 | 速记 |
|---------|---------|--------|------|
| `T(n) = T(n/2) + O(1)` | 二分查找 | O(log n) | 一半+常数 |
| `T(n) = 2T(n/2) + O(n)` | 归并排序、快排 | O(n log n) | 两半+线性合并 |
| `T(n) = T(n-1) + O(1)` | 线性递归（求阶乘） | O(n) | 减1+常数 |
| `T(n) = T(n-1) + O(n)` | 选择排序递归版 | O(n²) | 减1+线性 |
| `T(n) = 2T(n-1) + O(1)` | 斐波那契（无记忆） | O(2^n) | 减1但分两支 |

**怎么用**：
```python
# 问：这段归并排序的复杂度？
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # T(n/2)
    right = merge_sort(arr[mid:])   # T(n/2)
    return merge(left, right)       # O(n)

# 匹配模板：T(n) = 2T(n/2) + O(n) → O(n log n)
```

## 五、空间复杂度——不只CPU是资源，内存也是

### 什么是空间复杂度

和时间复杂度同理，只是衡量**内存使用量随N增长的趋势**，不是时间。

```python
# O(1) 空间：不随N增长
def sum_array(arr):
    total = 0          # 只用一个变量
    for x in arr:
        total += x
    return total

# O(n) 空间：随N线性增长
def copy_array(arr):
    new_arr = []       # 新建一个等长的数组
    for x in arr:
        new_arr.append(x)
    return new_arr

# O(n²) 空间：随N平方增长
def build_matrix(n):
    matrix = [[0]*n for _ in range(n)]  # n×n的二维数组
    return matrix
```

### 常见的空间换时间

```python
# 查找重复元素——时间O(n²)，空间O(1)
def has_dup_slow(arr):
    for i in range(len(arr)):
        for j in range(i+1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False

# 查找重复元素——时间O(n)，空间O(n)
def has_dup_fast(arr):
    seen = set()         # 额外的O(n)空间
    for x in arr:
        if x in seen:
            return True
        seen.add(x)
    return False
```

**空间换时间不是"作弊"，是工程上的标准做法。** HashMap/Set/Cache都是这个思路——多用一点内存，把O(n²)降到O(n)。

## 六、3个"你以为很快其实很慢"的反直觉案例

### 案例1：字符串拼接在循环里 → O(n²)

```python
# ❌ 每次拼接都创建新的字符串（Java/Python都是不可变字符串）
result = ""
for i in range(n):
    result += str(i)   # 每次都要复制整个result → O(n²)
# N=10000 → 约5000万次字符拷贝

# ✅ 用列表+join → O(n)
parts = []
for i in range(n):
    parts.append(str(i))
result = "".join(parts)
```

### 案例2：递归没有记忆化 → O(2^n)被当作"很快"

第一个想到斐波那契递归的人觉得"两行代码写完，优雅"——直到他们用n=45测试了一下。

```python
# fib(50)的递归树有多恐怖：
# 2^50 ≈ 1千万亿次调用
# 就算每秒10亿次，也要跑11天
# 加上memo → O(n)，秒出
```

### 案例3：ArrayList中间插入 → O(n)，但大家以为都"很快"

```java
// 在ArrayList第0个位置插入 → O(n)，因为后面所有元素都要后移
list.add(0, item);  // 10万元素 → 移动10万次

// 在LinkedList第0个位置插入 → O(1)
linkedList.addFirst(item);

// HashMap的put → O(1) 均摊
// 但HashMap的put在扩容时是O(n) —— 这就是为什么要知道"均摊复杂度"
```

## 七、时间复杂度速查表：常见操作和常见算法的复杂度

### 数据结构操作

| 操作 | 数组 | 链表 | HashMap/HashSet | 平衡树(TreeMap) |
|------|------|------|----------------|----------------|
| 访问(access) | O(1) | O(n) | - | O(log n) |
| 搜索(search) | O(n) | O(n) | O(1) | O(log n) |
| 插入(insert) | O(n) | O(1) | O(1)均摊 | O(log n) |
| 删除(delete) | O(n) | O(1) | O(1)均摊 | O(log n) |
| 最小/最大 | O(n) | O(n) | O(n) | O(log n) |

### 排序算法

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定 |
|------|------|------|------|------|------|
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n) | ❌ |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | ✅ |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ |
| 插入排序 | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| 计数排序 | O(n+k) | O(n+k) | O(n+k) | O(k) | ✅ |

### 图算法

| 算法 | 时间复杂度 | 空间复杂度 | 用途 |
|------|-----------|-----------|------|
| BFS/DFS | O(V+E) | O(V) | 遍历、最短路径(无权) |
| Dijkstra | O((V+E)log V) | O(V) | 最短路径(有权，正权) |
| 并查集(Union-Find) | O(α(n)) ≈ O(1) | O(n) | 连通性判断 |
