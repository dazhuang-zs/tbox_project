# 【AI Agent 系统教学 02】从 GPT 到 LLM：预训练与扩展定律

> 为什么同样用 Transformer，GPT-2 只会写废话，GPT-4 就能写代码？
> 核心答案就两个字：**规模**。但规模背后藏着精密的设计逻辑。

---

## 前言：Agent 建在什么之上？

你写 Agent 代码时，调用的 LLM API 背后有一套完整的"生产线"：

1. **收集数据**——互联网上所有公开文本
2. **预训练**——让模型学会"说人话"和基本知识
3. **指令微调**——让模型学会"听指令"
4. **对齐**——让模型变得有用且安全

Agent 开发者最常接触的是第 3 和第 4 步的产物（API 接口），但真正决定模型能力的，是第 1 和第 2 步。

**不理解预训练，你就无法理解：**
- 为什么一个模型的知识截止日期是 2023 年
- 为什么 Agent 有时会"编造"事实（幻觉）
- 为什么代码能力强的模型往往是"一直在训练"
- 为什么模型越大，越能在 Agent 任务中表现出"涌现能力"

## 一、GPT 进化史：一个关于规模的故事

### 1.1 从 GPT-1 到 GPT-4：一目了然

| 模型 | 发布时间 | 参数量 | 训练数据 | 关键创新 |
|------|---------|--------|---------|---------|
| GPT-1 | 2018.06 | 117M | BookCorpus（~4.5GB） | 证明无监督预训练有效 |
| GPT-2 | 2019.02 | 1.5B | WebText（~40GB） | 规模扩大有用，震惊学界 |
| GPT-3 | 2020.05 | 175B | Common Crawl（~45TB） | 上下文学习涌现，In-Context Learning |
| GPT-3.5 | 2022.03 | 175B | 代码增强 + 指令微调 | InstructGPT 流程，ChatGPT 诞生 |
| GPT-4 | 2023.03 | 推测 1.8T MoE | 更多 + 多模态 | 推理能力飞跃，Agent 应用爆发 |

关键转折点有三个：

**GPT-1 → GPT-2**：证明了"更大 = 更好"不是一句废话。GPT-2 的零样本能力让整个 NLP 社区意识到，无监督预训练可能已经学会了很多东西，只是之前模型太小了。

**GPT-2 → GPT-3**：175B 参数，45TB 数据。量变引起质变——**上下文学习（In-Context Learning）** 涌现了。模型不需要微调，给几个例子就能做新任务。这是 Agent 的"提示词"范式的基础。

**GPT-3 → GPT-4**：MoE 架构 + 多模态，推理能力飞跃。Agent 应用从"玩具"变成"工具"。

### 1.2 为什么 GPT-3 之前没有 Agent？

这个问题的答案，直接解释了为什么 Agent 是 2023 年之后才火起来：

- **GPT-2（1.5B）**：上下文学习能力极弱，给 10 个示例也记不住格式。给它一个工具定义，它大概率忽略。
- **GPT-3（175B）**：上下文学习突然有效。给 3 个示例，它就能理解任务。但"工具调用"仍然不稳定。
- **GPT-3.5（175B + 指令微调）**：能可靠地理解"请使用以下工具"。Function Calling 的雏形出现了。
- **GPT-4（推测 1.8T）**：不仅能理解工具，还能规划工具调用顺序、处理错误、自我纠正。

**Agent 不是凭空出现的。它是模型能力增长到某个临界点后，自然涌现出来的使用模式。**

## 二、自回归语言建模：预训练的核心任务

### 2.1 目标函数

所有 GPT 系列模型的核心训练任务只有一个：**预测下一个 token**。

```
输入: "猫追老"
目标: "鼠"
损失函数: Cross-Entropy Loss
```

训练时，模型看到"猫追老"，要预测"鼠"。不对就调整参数，对了就奖励。

整个过程是**自监督**的——不需要人工标注，文本本身就是标签。这就是为什么可以拿整个互联网做训练数据。

### 2.2 为什么"预测下一个词"这么有效？

这个简单的目标函数，实际上迫使模型学会了很多东西：

**语法**
```
"猫追___" → 需要知道动词后面要跟宾语
```

**语义**
```
"猫追老鼠" → 需要知道猫和老鼠的关系
```

**推理**
```
"因为下雨了，所以___" → 需要理解因果关系
```

**世界知识**
```
"中国的首都是___" → 需要记住事实
```

**代码理解**
```
"def fibonacci(n):" → 需要理解函数定义
```

预测下一个 token 需要模型同时理解语法、语义、推理、事实、代码。这比任何人工设计的训练任务都更全面。

### 2.3 训练数据质量的重要性

2026 年的共识：

> 数据质量比数据量重要，但前提是数据量足够大。

| 训练数据 | 特点 | 代表模型 |
|---------|------|---------|
| 纯网页文本 | 噪声大，质量参差 | GPT-3 |
| 过滤+去重 | 质量提升，减少幻觉 | Llama 3 |
| 代码+数学+推理 | 推理能力显著提升 | DeepSeek V3、Qwen 2.5 |
| 合成数据 | 可以定向增强弱项 | GPT-4、Claude 3.5 |

**对 Agent 开发者的启示**：你使用的模型，其训练数据直接决定了它在 Agent 任务中的表现。代码数据多的模型（如 DeepSeek Coder、CodeLlama），在工具调用、JSON 格式输出上天然更好。

## 三、扩展定律：Scaling Law 与 Chinchilla

### 3.1 原始 Scaling Law（2020）

OpenAI 在 2020 年发表的 Scaling Law 论文揭示了一个关键发现：

> **模型性能与模型规模、数据规模、计算量之间存在幂律关系。**

具体来说：
- 模型参数量翻倍 → 性能提升（但收益递减）
- 训练数据量翻倍 → 性能提升（但收益递减）
- 计算量翻倍 → 性能提升（三个因素中收益最稳定）

**公式简写**：

```
Loss ≈ N^(-α) + D^(-β) + C^(-γ)
```

其中 N 是参数量，D 是数据量，C 是计算量。

### 3.2 核心洞察：同时增大三者

Scaling Law 最重要的结论是：

> **如果只增大模型，不增大数据，模型会欠拟合（underfitting）。**

类似一个学生：
- 只增加学习时间（计算量），但教材不变（数据量）→ 边际收益递减
- 只增加教材数量（数据量），但不增加学习时间 → 学不完
- 同时增加教材和时间和大脑容量 → 效果最好

### 3.3 Chinchilla 最优计算（2022）

DeepMind 的 Chinchilla 论文更精确地回答了这个问题：

> **给定固定的计算预算，模型参数量和训练数据量应该按什么比例分配？**

**Chinchilla 法则**：对于每 1 个参数，应该训练约 20 个 token。

| 模型 | 参数量 | 训练 token 数 | 是否符合 Chinchilla |
|------|--------|--------------|-------------------|
| GPT-3 | 175B | 300B | 严重不足（1.7 token/参数） |
| Llama 1 | 65B | 1.4T | 接近（21.5 token/参数） |
| Chinchilla | 70B | 1.4T | 最优（20 token/参数） |
| Llama 3 | 70B | 15T | 远超（214 token/参数） |
| DeepSeek V3 | 671B MoE | 14.8T | 远超（22 token/参数，已接近最优） |

**为什么后来的模型（如 Llama 3）远超 Chinchilla 建议？**

因为 Chinchilla 的计算假设是"最优性价比"，但实际中：
- **更大的计算量总比小好**——只要你有钱，继续训总是有效果的
- **数据质量比数据量更重要**——Chinchilla 假设所有数据质量相同，但现实不是
- **涌现能力有阈值**——某些能力只在特定规模下出现，Chinchilla 最优解可能达不到这个阈值

### 3.4 Scaling Law 对 Agent 开发的意义

**为什么 Agent 任务需要更大模型？**

| 模型规模 | 能做什么 | 在 Agent 中能用吗 |
|---------|---------|-----------------|
| < 1B | 简单问答、分类 | 不能，Tool Use 几乎不可靠 |
| 1B-7B | 基础对话、简单指令 | 有限，只能做单步简单工具调用 |
| 7B-70B | 复杂推理、工具调用 | 可用，但可靠性不足 |
| 70B+ | 规划、推理、多步工具 | 可靠，适合生产环境 |
| 200B+ | 复杂 Agent 行为涌现 | 最佳，但成本高 |

**Agent 任务对模型能力的要求，天然高于普通对话。** 这就是为什么 Agent 应用在 2023 年 GPT-4 出现后才爆发——不是因为没有框架，而是之前的模型根本不够用。

## 四、训练流程详解

### 4.1 预训练的全流程

```
原始互联网数据（PB 级）
    ↓
清洗、去重、过滤
    ↓
Tokenization（分词）
    ↓
训练数据加载
    ↓
前向传播 → 计算 Loss
    ↓
反向传播 → 梯度更新
    ↓
重复万亿次
    ↓
基础模型（Base Model）
```

**时间线**：训练一个 70B 模型，在 8000 张 GPU 上需要 1-2 个月。

### 4.2 关键训练技术

**混合精度训练（FP16/BF16）**
- 用半精度浮点数存储参数和梯度
- 显存减半，速度翻倍
- BF16 比 FP16 更稳定（同样的指数范围，但精度更低）

**3D 并行**
- 数据并行（Data Parallel）：每个 GPU 处理不同批次
- 张量并行（Tensor Parallel）：把一层切分到多个 GPU
- 流水线并行（Pipeline Parallel）：不同层放在不同 GPU

**ZeRO 优化**
- ZeRO Stage 1：优化器状态分片
- ZeRO Stage 2：梯度分片
- ZeRO Stage 3：参数分片
- 让训练超大规模模型成为可能

**学习率调度**
- Warmup：前几千步从小学习率升到目标
- Cosine Decay：之后按余弦曲线降低
- 最终学习率约为初始的 1/10

## 五、预训练后：从 Base Model 到 Chat Model

### 5.1 Base Model 不是你能用的模型

预训练完成后，模型（Base Model）的能力：
- 能续写文本
- 能回答问题——但不太会按你的格式回答
- 会输出"基于给定的上下文，答案可能是..."而不是"答案是 42

你需要的 Agent 模型（Chat Model/Chat 模型）在 Base Model 基础上还需要两步：

```
Base Model → 指令微调 → 对齐 → Chat Model
```

**指令微调（Supervised Fine-Tuning, SFT）**
- 用高质量的人工标注数据（问答对）
- 让模型学会"像助手一样回答"
- 数据量：几万到几十万条
- 关键：不是学新知识，是学**交互模式**

**对齐（Alignment）**
- RLHF（基于人类反馈的强化学习）或 DPO（直接偏好优化）
- 让模型学会说"我不知道"而不是瞎编
- 拒绝有害请求
- 保持有用性

### 5.2 为什么 Agent 开发者需要知道这些

**你用的是什么模型？**

| 模型类型 | 特点 | 适合 Agent 吗 |
|---------|------|-------------|
| Base Model | 原始预训练，无指令能力 | 不适合，不会听指令 |
| SFT Model | 指令微调，能回答 | 基本可用，但不太会拒绝 |
| RLHF Model | 对齐后，有用且安全 | 最佳，但可能过于保守 |
| Custom Fine-tune | 在特定数据上微调 | 适合特定领域的 Agent |

**LoRA 微调**：如果你想让 Agent 在特定领域表现更好，可以对 Chat Model 做 LoRA 微调。只更新少量参数（~0.1%），就可以让模型适应特定任务。

## 六、大模型的能力涌现

### 6.1 什么是涌现能力？

**涌现**：模型规模达到一定程度后，突然出现的能力——这些能力在较小模型中完全不存在。

| 涌现能力 | 出现规模 | 对 Agent 的意义 |
|---------|---------|----------------|
| 上下文学习 | ~1B 开始，~175B 稳定 | 给几个示例就能做任务 |
| 思维链推理 | ~10B 开始出现，~70B+ 稳定 | Agent 能"边想边做" |
| 工具调用 | ~7B 开始，~70B+ 可靠 | Agent 能使用外部工具 |
| 代码生成 | 与推理能力同步涌现 | Agent 能写代码执行 |
| 自我纠错 | ~70B+ | Agent 能发现自己的错误并修正 |

### 6.2 涌现的机制

目前对涌现的理解还不完全，但有几种主流解释：

**能力组合论**：复杂任务需要多个子能力的组合。小模型有子能力 A，但缺子能力 B，所以做不了任务。当规模大到同时拥有 A 和 B，任务突然能完成。

**表征清晰度**：小模型也"知道"概念，但表征模糊。大模型有更清晰的表征，能准确使用。

**注意力资源**：大模型有更多 Attention Head，可以同时处理多种信息，这是小模型做不到的。

**对 Agent 开发者的启示**：如果你发现当前模型在 Agent 任务上表现不稳定，**不一定是你代码的问题**，可能是模型能力还没到涌现的阈值。

## 七、2026 年预训练的新趋势

### 7.1 数据墙

GPT-4 级别的模型已经消耗了互联网上几乎所有高质量文本。2026 年的预训练面临"数据墙"：

- 互联网文本总量有限（约 10^14 token）
- 高质量文本更少（约 10^12 token）
- 已经用掉大部分

**应对方案**：
- 合成数据：用教师模型生成训练数据
- 多模态数据：文本之外的图像、视频、音频
- 领域数据：论文、代码、教科书等高质量数据

### 7.2 计算墙

Scaling Law 的"暴力美学"正在碰壁：

- 训练一个 GPT-4 级别的模型需要数亿美元
- 电力、冷却、硬件成为瓶颈
- 边际收益在递减

**应对方案**：
- MoE 架构：同样参数，只激活一部分
- 更好的训练效率：Flash Attention 3、更优的并行策略
- 小模型蒸馏：大模型教小模型

### 7.3 后训练时代

2026 年，预训练不再是唯一重点：

- 更多计算花在**后训练**（Post-Training）
- 包括指令微调、对齐、RLHF
- 同样的 Base Model，不同的后训练策略 → 完全不同的能力

DeepSeek 的 R1 模型就是典型例子：基础模型不变，通过强化学习训练"推理能力"，让模型在数学、代码等推理任务上大幅提升。

## 总结

| 关键概念 | 一句话 | 对 Agent 的影响 |
|---------|--------|----------------|
| 自回归训练 | 预测下一个 token | 决定了 Agent 是"逐 token 生成"的 |
| Scaling Law | 更大 + 更多数据 = 更好 | 大模型 Agent 能力远强于小模型 |
| Chinchilla | 最优参数-数据配比 | 决定了你用的模型训练是否充分 |
| 涌现 | 能力在规模达到阈值后突然出现 | Agent 的 Tool Use 是涌现能力 |
| 数据墙 | 高质量文本有限 | 未来 Agent 可能需要专用模型 |

从下篇文章开始，我们将进入**对齐技术**——RLHF 和 DPO 是如何让模型从"会说话"变成"有用且听话"的。
