# 我扒了CSDN新晋作者热榜的API，第一名果然是用AI写的

## 起因

今天逛CSDN排行榜，发现一个不对劲的事：新晋作者热榜第一名，热度2744，第二名热度1142。**第一名比第二名高出一倍还多。**

这不太正常。正常的榜单，相邻排名之间的热度差通常是渐进的。

于是我做了每个技术人都会做的事——打开F12，找API。

## 先看数据

CSDN排行榜的数据是从 `blog.csdn.net/phoenix/web/v2/rank` 这个接口加载的。直接调了一发，拿到新晋作者榜 TOP 5：

| 排名 | 昵称 | 热度 | 文章标题 |
|:---:|------|:---:|------|
| 1 | **AI砖家** | 2744 | 告别中英文混杂！Claude Code 纯中文输出配置完全指南 |
| 2 | **AI未来范式** | 1142 | Python基础：变量的定义、命名规则与数据类型入门 |
| 3 | 流浪001 | 723 | C++类和对象详解 |
| 4 | Tech智姬 | 600 | Token消失了？Codex、Claude的token余额这样查 |
| 5 | 冯朝臣 | 569 | Claude Code 接入本地大模型Qwen3.6 |

有两件事引起我的注意：

**第一，昵称。** 第一名叫"AI砖家"，第二名叫"AI未来范式"。用户名里直接带"AI"标签，这相当于在自己脑门上贴了张"我是用AI写的"的标签。我不知道这是坦诚还是讽刺。

**第二，热度断层。** 从2744断崖式跌到1142，这个差距不像自然竞争的结果。一个周更新的新晋作者榜，第一和第二之间不会有这么大的热度鸿沟——除非第一名的流量来源不完全是"读者觉得写得好"。

## 点进去看看写了什么

### 第一名：AI砖家 —《Claude Code 纯中文输出配置完全指南》

文章结构是这样的：

```
基础篇 → 进阶篇 → 终极方案 → 避坑指南 → 总结
```

标准的AI生成三段式升级结构。标题也很有那味："一招让你的 AI 编程助手秒变'本土化'高手"、"彻底告别英文干扰"——这是典型的"请写得生动一点"prompt 产物。

更有意思的是内容。文章里推荐了一个叫 `@khalilgao/openclaude-cn` 的 npm 包，号称可以"让 Claude Code 底层调用 DeepSeek、智谱 GLM、通义千问等国产模型"。

我在 npm 上搜了一下这个包——**不存在。**

这是典型的 LLM 幻觉：模型被要求写一篇"Claude Code 汉化教程"，它在知识边界之外自己编了一个工具名出来。最妙的是，这篇文章的热度是2744，排第一。

### 第二名：AI未来范式 —《Python基础：变量的定义、命名规则与数据类型入门》

这篇文章更"标准"。打开看一眼就知道是 AI 写的：

- 📚💡⚠️📊✅❌ 每个段落开头一个 emoji
- "核心概念与背景 → 技术原理详解 → 实践应用 → 常见问题与解决方案 → 最佳实践 → 本章小结" — 教科书式的AI文章骨架
- 标题"变量的定义、命名规则与数据类型入门"在正文里作为小标题反复出现至少四次
- 代码示例里有个 `PythonDemo` 类和变量教程毫无关系，纯粹凑代码块
- ASCII 图表（┌──────────┐）——某些 LLM 特别喜欢画这种终端风格框图

一个学 Python 的人看到这篇文章，学到的东西可能还不如直接问一遍 DeepSeek。

## 这说明了什么

**第一，CSDN 的内容生态正在被 AI 快速渗透。** 这不是"个别案例"，新晋作者榜前两名都是明牌 AI 写作。而且他们都排在前面，说明 AI 文章在 CSDN 的推荐算法下是能拿到流量的。

**第二，"收藏"这个指标已经被污染。** AI 文章的结构天然适合"快速浏览 → 顺手收藏"的阅读模式。标题承诺大（"完全指南""入门到精通"），内容结构清晰（分段+代码+表格），读者两分钟扫完点个收藏就走了。但算法看到的是"高收藏率 → 推更多流量"。这个循环一旦转起来，纯手工写深度内容的人就会被挤出流量池。

**第三，CSDN 目前没有有效的 AI 内容识别和治理机制。** 用户名叫"AI砖家"还能排第一，这说明要么没有检测，要么检测了但不管。无论是哪种，对认真写内容的作者都是一种打击。

## 我们这些写作者怎么办

说实话，这个问题没有简单的答案。但我有几个想法：

**别模仿 AI 的写法。** 现在 CSDN 上越来越多的文章长得一模一样——都是八股结构、emoji 标记、三段式升级——读者已经开始审美疲劳了。你的差异化恰恰在于"不AI"：写只有你遇到过的 bug，贴只有你机器上能截图到的运行日志，讲只有你踩过的坑。

**用数据建立壁垒。** AI 能编教程，但编不出你项目里的真实性能数据、你生产环境的具体报错堆栈、你做的 A/B 测试结果。这些东西是护城河。

**写"反AI"的结构。** AI 文章的结构是预测出来的最可能结构——概念→原理→实践→总结。你偏不这么写。你可以从一次线上事故开始，倒推原理，中间插一段和同事的争吵，最后发现问题是配置文件少了个逗号。这种叙事 AI 写不出来。

## 结尾

我用五分钟写了个 curl 就拿到了这些数据。CSDN 如果想要治理 AI 内容，技术上并不难。难的是它愿不愿意。

毕竟，AI 文章也是在贡献日活和内容量。对平台来说，是人写的还是 AI 写的，可能没那么重要。
